Application Monitor Triggers - Feature Note

Goal
Add optional rules that automatically place selected applications on an assigned monitor when their main window opens.

Example rules
- Paltalk.exe -> Monitor 3 -> Maximize
- Discord.exe -> Monitor 2 -> Keep its current size
- chrome.exe -> Monitor 1 -> Set a saved size and position

What the app can do
This Python application can implement this feature. It already uses native Windows window-management APIs through pywin32 to find and move application windows between monitors. Python is not a limitation: the same Windows APIs can be called from Python as from C or C++.

Suggested trigger behavior
1. Run a lightweight background watcher while the app is open.
2. Detect a new eligible top-level window.
3. Identify its owning executable.
4. Match it to a saved application rule.
5. Move it to the selected monitor, optionally set its size/position, and optionally maximize it.
6. Retry briefly when an application uses a splash screen or creates its main window after a delay.

Optional enforcement
Each rule can include "reapply if moved." When enabled, the watcher can move a matched window back to its assigned monitor if it is manually dragged away. This should remain optional because some people will want to move windows freely.

Practical notes
- Use the executable name/path and, where useful, the window title/class so rules select the real main window rather than a splash screen or dialog.
- Ignore system windows and the app's own helper/overlay windows.
- Let users enable/disable individual rules and test a rule before saving it.
- This is comparable to DisplayFusion's "Window Created" triggers, but implemented as a native feature of Windows Resurface.

Current project fit
The existing Screen Mover already enumerates Windows monitors and moves windows using pywin32. Application Monitor Triggers would build on that capability by adding saved application-to-monitor rules and a background window watcher.
